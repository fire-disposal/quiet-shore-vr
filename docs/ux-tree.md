# UX 树：谁在什么状态下能做什么

状态：设计稿（2026-11-12）。只写结构与触发，不写样式；样式见 `docs/ui-system.md`（分支 `feat/ui-system`）。

这份文档回答三个问题：**一个会话从进入到结束经过哪些状态、每个状态下谁能触发什么、触发之后必须看到什么。** 按它来实现，界面可以有多种排法，但状态与触发不能少。

## 0 事实：四个面、四种输入

| 面 | 谁在用 | 能输入什么 | 现在能做什么 |
| --- | --- | --- | --- |
| WebXR 患者页 | 患者（躺卧） | 一个物理键（2D 态＝确认，XR 态＝停止）；口头说停 | 进入、停 |
| 平板控制台 | 技术员 | 触屏（BLE） | 选场景、强度、语音、SUS、开始/结束/断开连接 |
| 头显控制台 APK | 技术员（戴在患者头上） | 触屏/注视 | 拉起页面、电量、诊断、退出 |
| 场景镜像 | 技术员 | 只看 | 患者视野 |

> 关键约束：**患者只有一次按压和一次停止。** 所有复杂动作必须落在技术员那一侧，且不能要求技术员在会话中去操作患者头上的头显。

## 1 状态机（会话）

```text
idle ──技术员开始──> entry ──患者按压──> calibrating ──记录完成──> running
  ▲                     │                                          │
  │                     └─20 s 未按压 → 壳层重拉（最多 2 次）        │
  │                                                                │
  └── ended <── stopping <── 患者停 / 技术员结束 / 断开连接 / 链路断（5 秒未恢复即退出） / 摘下头显
```

| 状态 | 患者看到 | 技术员必须看到 | 技术员可做 |
| --- | --- | --- | --- |
| `idle` | 入口页（一句指令） | 配对状态、当前场景、可开始 | 选场景、设定时长/强度、开始 |
| `entry` | 入口页（等待按压） | "等待患者确认" + 已过秒数 | 重拉一次、取消、改场景（会重新拉起） |
| `calibrating` | 记录卡片（保持不动） | "校准中" | 什么都不做；唯一例外是结束 |
| `running` | 场景 | 时长、强度、体位、**当前场景** | 切场景、调强度、放语音、开 SUS、结束、断开连接 |
| `stopping` | 渐出 | "正在结束" | 结束（幂等）；**场景/强度被拒绝** |
| `ended` | 结束页提示 | 会话摘要、SUS 归档入口 | 开下一轮 |

## 2 触发规则（一张表读完整套权限）

| 动作 | 来源 | 允许状态 | 确认 | 必须的回读 |
| --- | --- | --- | --- | --- |
| 进入训练 | 患者按压 | `entry` | 无（这次按压就是确认） | 页面进入 `calibrating` |
| 选/切场景 | 平板 | `idle` / `entry` / `running` | **无**（即时生效） | state 的 `scene` + 镜像跟着换 |
| 调强度 | 平板 | `running` | 无 | state 的 `floatLevel` |
| 放语音 | 平板 | `running` | 无 | `voiceId` |
| 开 SUS | 平板 | `running` | 无 | `calibrating`? -> 面板可见 |
| 结束会话 | 平板 | `running` | 一次（"结束本次"） | 进入 `stopping` |
| 结束 | 平板 | 会话中 | 不确认 | ≤1 s 内进入 `stopping` |
| 断开连接 | 平板 | 任意 | 不确认 | 回初始态、关闭自动重连；头显断链 5 秒未恢复即退出 XR |
| 患者停止 | 头显物理键 | `calibrating` / `running` | 无 | 同上 |
| 重新拉起 | 壳层 | `entry` 超时 | 自动（≤2 次） | 页面重回 `entry` 并显示提示 |

三条硬规则：

1. **结束与断开连接不参与任何模态**：任何面板、展开块、说明页都不能让它们需要两次点击。急停已废弃（2026-11-12 决定）。
2. **即时生效的动作不回弹**：切场景、调强度在按下的一帧就发命令，界面只显示"已发/已回读"，不显示"待确认"占位。
3. **拒绝要说下一步**：`stopping` 时点场景，要明确"正在结束，稍后再切"，而不是静默。

## 3 UX 树（页面与层级）

### 3.1 平板（主控）

```text
配对页 Pairing
├─ 扫描列表 → 连接 → CLAIM（第一台接管，第二台显示"已被占用"）
└─ 权限缺失 → 就地提示"打开定位/蓝牙"

控制台 Console（单屏，不滚动整页）
├─ 命令栏（常驻，不随内容滚走）
│   ├─ 连接态点位 + 头显名/电量（若上送）
│   ├─ 当前场景名
│   ├─ 会话态："未开始 / 记录体位 / 进行中 mm:ss"
│   └─ i（说明） · 断开连接
├─ 看板（四个数，都是真数据）
│   └─ 时长 │ 强度档 │ 体位 mix │ 漂浮 mm
├─ 快捷动作（会话中也可用）
│   ├─ 场景条：四个场景横排，当前用强调色填充，点击即切
│   ├─ 强度：− / 档位 / ＋（下限 0、上限由场景舒适级决定）
│   └─ 语音：当前句 + 下一句 / 序列（进入语音抽屉）
└─ 次级（可折叠 / 可滚）
    ├─ 会话启停与时长
    ├─ 场景镜像（患者视野）
    ├─ 视线/体位仪表
    └─ SUS（逐题、目视、代答、归档）
```

要点：**会话中只剩"看板 + 快捷动作"**，其余收进次级区；这样技术员在会话里看到的每一块都与"现在能按的东西"有关。

### 3.2 头显控制台 APK

```text
Home
├─ 电量横栏（条 + 精确百分比 + 充电态）
├─ 当前场景（只读，来自平板的选择）
├─ 进入训练（唯一拉起 FxR 的按钮，3 s 冷却）
└─ 设置 / 帮助 / 退出
```

它**不是**第二块控制面：场景、强度、语音都归平板；这里只负责"把页面拉起来"和"看住设备状态"。

### 3.3 患者页（WebXR）

```text
入口页（只有一件事）
├─ 一句话：按一下头显右侧的按钮
├─ 按钮位置图（头显/手柄）
├─ 状态行（设备/连接/需要重按）
└─ 页脚：不适请告知工作人员

会话内
├─ 场景（全屏）
├─ 字幕卡（语音播放时）
├─ SUS 卡片（技术员开启时，注视 3 s 选中）
└─ 记录卡片（进入后的一次）
```

入口页**不再预告场景名**：场景可以在会话中换，预告只会骗人。

## 5 已知缺口（实现前要补的，按优先级）

| 缺口 | 影响 | 最小做法 |
| --- | --- | --- |
| **拒绝原因不回传**：页面拒绝一次切换/强度时只在自己的屏幕上写一行状态，平板看不到 | 违反 §2 规则 3 | 页面 → 服务端新增一条 `{"type":"notice","text":"…","tone":"error\|ok"}`；服务把它变成 BLE 的 `UiEvent` 给平板（协议属于追加） |
| ~~平板没有头显电量~~ | 已补：服务在 `flags` 文档追加 `battery:{level,charging}`（平板只需解码） | — |
| 会话中的"当前场景"以 state 回读为准，但切场景后 state 最多晚 1 s | 快捷动作的"已生效"反馈慢 | 页面在 `scene:` 处理后立刻 `sendStateNow()`（已做），平板在按下时先本地高亮、回读后校正 |
| ~~强度上限依赖场景 `comfortLevel`~~ | 已补：`caps.floatMax` 随 state 帧下发（场景知识经 `planMotion` 携带），平板步进器据此夹紧 | — |

## 6 明确不做

- 不做"训练中弹确认框"：任何确认都会把技术员的手从控制上挪开。
- 不在会话中改站立足高、改模式：这两个会改变整个世界几何，只能会话前改。
- 不让头显控制台成为第二块控制面。
- 不把诊断信息放到患者屏上（连接态一行足够）。
