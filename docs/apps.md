# 应用层级（App level）

状态：2026-11-12 起草并落地 H1–H4。引入原因：问卷产品线要从训练里独立出来，而
"顶栏只有一个 `i`、只有一份说明书、主区域只有一套内容"这三件事都是按单应用写死的。

实现：`app:training|app:questionnaire` 命令下行；页面把 `app` 放进状态 JSON，头显转发到
`flags`，平板顶栏显示的是头显回报的值。切应用在会话中拒绝；`i` 按当前应用打开各自说明书。
问卷题目由页面 `src/questionnaire/registry.ts` 单一来源下发，平板只渲染收到的题目与选项；
训练记录与问卷记录写同一份本机记录文件，用 `app` 字段区分。

## 1 什么是"应用"

**应用 = 一个可在主区域切换的产品面**，各自拥有：主区域内容、自己的说明书、自己的
会话/记录语义。当前两个：

| 应用 | 主区域 | 说明书 |
| --- | --- | --- |
| 训练（session） | 会话/场景/语音/量表（现有四段） | 现有《操作说明》：校准、分段、结束 |
| 问卷（questionnaire） | VR 问卷环境：题目、作答记录、导出 | 问卷自己的说明：如何施测、如何导出 |

外壳（顶栏、导轨、初始页）不随应用变化；**变的是主区域与说明书的指向**。

## 2 顶栏的布局约定

```
[信号] 已连接 EEFF │ 两条电量条 │ [当前应用 ▾] │ (i) │ [断开连接]
                                   ↑ 电量列左让位给它
```

- `当前应用 ▾`：平时只显示应用名，点击向下弹出列表切换。
- `(i)`：**指向当前应用的说明书**——先切应用，再点 `i`，打开的就是它自己的说明。
  没有"全局说明书"这个入口（通用操作写在各自说明书的第一节）。
- 电量条为它让出宽度：两条读数各收窄，仍保持"文字在条内、色带在条内"。

## 3 同步

- 控制端切换应用 → 发命令（建议 `app:<id>`）→ 页面切换主区域内容；
- 页面把自己的当前应用回报（走现有 JSON 通道的 `flags` 或独立文档），
  控制端顶栏因此显示的是**头显正在跑的应用**，而不是本地点了什么；
- 两者不一致时（切换失败/断链），顶栏显示头显侧的值，并在链路横幅里说明。
