# 性能审计与优化顺序

目标设备：PICO G2 4K，Adreno 540，Firefox Reality 10 / Gecko 78，3DoF，双目 WebXR。

结论：场景计数已经健康，当前主要成本不是几何量，而是**每帧像素量、片元着色器和透明叠层**。

## 1. 资源基线

| 场景 | Draw calls / 眼 | 三角形 / 眼 | 材质 | 灯光 |
| --- | ---: | ---: | ---: | ---: |
| 湖畔高 | 24 | 43.8k | 23 | 2 |
| 湖畔低 | 21 | ~10k | 20 | 2 |
| 训练病区高 | 20 | 5.7k | 19 | 3 |
| 训练病区低 | 20 | 4.9k | 19 | 3 |
| 暖石浴室高 | 18 | 2.7k | 16 | 3 |
| 暖石浴室低 | 17 | 1.9k | 14 | 2 |
| 空间实验 | 9 | 0.55k | 6 | 3 |

XR 会把场景渲染两次，所以湖畔实际约 48 次场景 draw / 帧；这仍然很轻。三角形和 draw call 不是第一优先级。

## 2. 真正的瓶颈

| 优先级 | 证据 | 成本 | 判断 |
| --- | --- | --- | --- |
| P0 | `renderer.ts` 高清 XR 使用 1.25 framebuffer scale（本文件为历史性能分析），且默认请求 MSAA | 双目约 8.29M 像素/帧，MSAA resolve 增加带宽 | 最大的确定性成本 |
| P0 | 天空球覆盖 100% 像素，约 9 次 `hash21`、2 次噪声、`acos`、多次 `pow` | 全屏片元 ALU | 湖畔首要 ALU 成本 |
| P1 | 水面 5 个 `sin`、5 个 `cos`、4 个 `pow`，高覆盖 | 大面积 SFU 与片元 | 湖畔第二成本 |
| P1 | 病区/浴室/实验大量 `MeshStandardMaterial` + 2 到 3 盏灯 | 房间几乎全屏 PBR | 房间首要成本 |
| P2 | 云、雾、薄雾、泡沫、光晕、鸟叠加透明混合 | 地平线附近多次 overdraw | 中等 |
| P2 | 1200 个双面 alphaTest 草片 | 近景 discard 与 overdraw | 中等 |
| P2 | 云、雾、鸟每帧重传实例矩阵 | CPU/驱动上传 | 低到中 |
| P3 | HUD 每 2 秒上传 1024×128 canvas | 周期性微卡顿 | 可测 |
| P3 | 输入 raycast、校准 `Vector3`、HUD 统计分配 | GC 压力 | 低 |

## 3. 实例复用现状

已经正确使用 `InstancedMesh` 或按材质合并：

- 湖畔：山脊、树干、树冠、草、花、芦苇、卵石、岩石、栈桥、云、雾、薄雾、鸟。
- 训练病区：天花板面板。
- 浴室/病区：静态房间按材质批处理。
- 空间实验：静态面板与柱子共享几何/材质。

仍需处理的高价值候选：

1. 实验场景 4 根柱子改为一个 `InstancedMesh`，减少 3 draw，低风险。
3. 5 个单位 billboard 共用同一 `PlaneGeometry`，只省内存。
4. 雾和薄雾合并为一个 instanced mesh，减少 1 draw 和 1 材质。
5. UI 面板背景纹理按尺寸/主题缓存，单位平面共享，实验 UI 延迟构建。

“clone 实例复用”不是当前最大杠杆；继续把每帧像素成本降下来更有效。

## 4. 推荐顺序

### P0 先做，低风险

1. **把 XR 抗锯齿与 2D 抗锯齿拆开**。XR 默认关闭 MSAA，保留 `?aa=1` 作为调试开关。
2. **XR framebuffer scale 分档**：高清 0.85，低画质 0.70。先 A/B 0.85 与 0.90，确认文字和准星可读。
3. **HUD 使用真实 `renderer.info.render`**，不再只用设计期 `measureObject`。现在已改为实际 calls/triangles，XR 中会显示双眼总量。
4. 记录 10 秒 p50/p95 帧时间，和 `?quality=high&aa=0/1` 对比，再决定最终档位。

### P1 画面设计优化

1. 天空改为加载时烘焙的等距柱状/CubeTexture 或绘制好的 CanvasTexture 穹顶；保留太阳位置、地平线和色调。
2. 水面改为可平铺法线/闪光纹理加滚动 UV，固定高光指数，远处混合到雾色。
3. 病区/浴室的墙、地、柜、床品从 Standard 降到 Lambert；只保留陶瓷、金属、水和叶片的高光。
4. 病区减少一盏方向光；浴室/实验各减少一盏点光。先用截图 A/B，确认体积感没有明显损失。

### P2 叠层与 CPU

1. 云 12 减到 6，薄雾 5 减到 2，雾烘进天空；保留近岸泡沫。
2. 草改为 600-700 个实例，限制深度和范围，远层用更大的卡片。
3. 云/雾/鸟的实例矩阵改 `DynamicDrawUsage`，或把漂移放进顶点着色器，保持矩阵静态。
4. 实验 UI 首次进入时构建，面板纹理缓存，单位平面共享。
5. 校准每帧的 `new Vector3` 改为复用；raycast 无目标时提前返回。

### P3 测量驱动

只有当 HUD 证明顶点或 draw call 真的成为瓶颈时再做：

- 分块 instanced field 并修正 bounding sphere。
- 远树冠降低细分。
- 卵石/岩石合并。
- 更激进的 culling。

## 5. 不能直接下的结论

- 合成 bench 不是 PICO 实测；不能把 bench 数字外推成设备 FPS。
- Adreno 540 是否完全遵从 MSAA/scale 请求，需要设备 A/B。
- 天空/水面烘焙后的观感必须和当前画面并排检查，不能只看 FPS。
- 不能为了性能把患者端场景做成低质灰盒；先保氛围，再减成本。

## 6. 验收指标

- 湖畔、病区、浴室各记录 30 秒：p50/p95 帧时间、实际 draw/triangle、热降频前后。
- 同一视角 A/B：scale 1.0 / 0.9 / 0.85，AA 开/关。
- 视觉验收：文字、准星、地平线、水面高光、房间体积感。


## 7. 已落地的小改动

- HUD 改用 `renderer.info.render` 的实际 calls/triangles，并显示 120 帧 p95 帧时间。
- XR 默认保留 AA 和 1.25 framebuffer scale，视觉优先；`?aa=0`、`?scale=` 是显式性能 A/B 工具。
- 低画质默认 0.85 scale 且关闭 AA；不把性能档强加给患者。
- 空间 UI 的标题/正文网格共享一个单位平面，减少重复几何。
- 校准循环复用 forward 向量，不再每帧分配 `Vector3`。

这些改动让性能可见，并提供显式降档；默认仍以画面舒适为先。P0/P1 的天空、水面和房间材质优化仍需设备 A/B 后决定。

## 8. 视觉优先修订

当前设备 FPS 尚可，默认恢复 XR AA 和 1.25 framebuffer scale；`?aa=0`、`?scale=` 仅作为设备 A/B 与低配逃生口。湖畔三个悬浮多面体已删除，减少无意义装饰与选择负担。
