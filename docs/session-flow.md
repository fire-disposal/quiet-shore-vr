# 会话流程

一次会话从技术员启动到结束，只有这一条路径。范围见 `docs/core.md`，协议见 `docs/protocol.md`。

## 1 步骤

| 步 | 谁做 | 发生什么 |
| --- | --- | --- |
| 1 | 技术员 | 平板连上头显（BLE 自动匹配 `QuietShore` 即连，无设备列表），完成 `HELLO QS2 1` 与 `WELCOME QS2 1 <capMask>` 握手后点启动，发 `enter` |
| 2 | 头显壳 | 拉起 Firefox Reality 打开 `127.0.0.1:8130`，入口监督开始计时 |
| 3 | 患者 | 在头显上按一次按钮进入 WebXR，这是浏览器强制的用户手势，也是只属于患者的一次交互 |
| 4 | 患者 | 落在内置准备间 `prep`：无陈设、无环境声、无运动。适应窗口 60 秒，两块屏幕都不显示秒数，只显示适应中或可记录，技术员可用 `adapt:skip` 提前结束 |
| 5 | 技术员 | 调患者体位，点记录体位发 `calibrate`。卡片要求保持不动 1.8 秒，随后 3 秒取样取平均，超 9 秒强制落地；卡片期间世界完全静止 |
| 6 | 技术员 | 体位记录后正式场景解锁，选卡发 `scene:<id>`。`washroom` 第一帧就是站立视角，仰卧场景从真实天花板开始并由一次排定的起身转到站立视角 |
| 7 | 技术员 | 会话中调整：强度 `float:level:0-100`、体位 `posture:rise`/`posture:lower`/`posture:mix:0-100` 与 `anim:duration:4000-20000`、语音 `voice:*`、视图 `view:anim:up|down|recenter` |
| 8 | 技术员 | 会话中可再发 `scene:<id>` 热切换，内容预建，校准帧与视线偏移保留；`posture:stop` 可随时冻结 |
| 9 | 技术员或患者 | 结束。患者随时可以说停或按一次确认键；技术员点结束。两者走同一条渐出，停止优先于一切排队运动 |
| 10 | 技术员 | 需要量表时切到问卷应用，在问卷面作答并归档 |

## 2 会话中可做与不可做

- 患者只有一次交互：按确认键开始，按确认键可随时停止。不存在模式切换按键。
- 技术员动作即时生效，不二次确认，因为都可撤销或本身就是停止。
- 没有分段、没有 `program:*`、没有自动推进、没有计划时长。一次会话就是手动选场景、手动调体位与强度、手动结束。
- **没有急停**：停止语义由确认键、技术员结束与取下头显承担，`结束` 是与 `断开连接` 并列的唯一会话出口。

## 3 校准

- 只在技术员点击记录体位时发生，没有计时器自动触发，也没有进度条倒计时。
- 会话中可重做（`calibrate`）：不结束会话，不清零会话时钟与台账。
- 只取头部朝向与实测体位，不要求患者看向任何方向。世界静止时的修正量由场景声明的 `viewer` 决定。

## 4 问卷面

- 切到 `questionnaire` 时页面换成内置房间 `survey`（六面素色一块天光、无陈设、无环境声），切回时恢复技术员原来的场景。会话中拒绝切应用。
- 题目由 `src/questionnaire/registry.ts` 单一来源经 JSON 通道下发，平板只渲染收到的题干与选项。
- 患者注视选项作答，技术员也可代答（`sus:show:*` / `sus:answer:*`）。作答结果走 JSON 通道的 `sus` 文档，按稳定键去重后归档。

## 5 记录与出口

- 训练会话摘要、问卷答卷、行为事件写同一份本机记录，用 `app` 字段区分，导出为一份 JSON，走系统分享。默认不上传，不做 OTA。
- 结束后页面回待机，技术员断开连接或取下头显，一次上机结束。
