# 会话流程与可控性：把"一次一个场景"变成"一段可编排的流程"

状态：2026-11-12 起草，同日按现场反馈改为「准备间 → 标定 → 正式场景」并落地。动机有三条，都来自现场：

1. 护士长提出**流程要更长**：一次上机希望依次走几个场景，而不是一个场景看到结束。
2. **校准的触发方式说不清**：技术员不知道什么时候会进入校准、为什么进入、能不能跳过。
3. 头显里那一步**总要人手工点一次**（FxR 打开页面、把窗口摆到面向的位置）。

这份文档定"会话长什么样"，落地顺序见 §6。

## 1 现状

- 会话 = 技术员启动 → 患者按一次 → **进入内置准备间（空灰房间）** → 技术员记录起始体位 → 选正式场景或启动段计划 → 在场景里操作 → 结束。
- 场景列表在患者真正进入 XR 前是锁定的：进 XR 并完成标定后，平板才把正式场景解锁为可选；选中只是标记，按 `进入正式场景/切换场景` 才发出 `scene:<id>`。
- 准备间是内置特殊场景（`prep`），不出现在场景卡列表里；它的镜像是正常工作的，技术员能看见患者在空房间里的视角。
- 校准随时可触发：首次记录起始体位后，会话中 `重新校准` 不结束会话，也不清零会话时钟与台账。
- 场景切换走动态换内容（`switchSceneLive`），校准帧与视线偏移保留。
- 平板可编辑**段编排**：每段声明场景、时长、语音序列、强度上限；默认空计划 = 单段、不限时。
  `program:<auto>:<scene>,<秒>,<voice>,<cap>;...` 一次写入；页面按墙钟自动推进，也可 `下一段`。
- 会话页常驻流程带（第 n/N 段 · 场景 · 剩余/不限时 · 自动/手动），页面经 JSON 通道回传段进度。
- 台账按段记录：序号、场景、实际秒数、计划秒数、段内峰值；同一场景的两段不合并。
- 场景之间的过渡仍是硬切（`docs/scene-switch.md` 已记为已知缺陷）。

## 2 目标模型

一次会话 = **准备间（内置）→ 标定 → 正式场景 → 若干段（可选编排）**。

准备间不是训练内容：它没有陈设、没有声音、没有运动，只给患者熟悉头显、给技术员调整体位
和记录起始朝向。正式场景只在患者已经身处 XR、标定完成之后才解锁；选中一张卡不等于进入，
按 `进入正式场景` 才换内容，校准因此不会丢。

一次会话的正式内容 = 一段**编排**（program），由若干**段**（segment）组成。
计划在平板上编辑，页面执行；默认不建计划，等价于单段、手动结束。

```text
program:<auto 0|1>:<scene>,<seconds>,<voice>,<cap>;
                   <scene>,<seconds>,<voice>,<cap>;...
seconds = 0  → 不限时；voice = none；cap = 0 → 场景自己的上限
```

```
会话 = [ 段1: 场景A × 6 分钟 · 语音 sequenceA · 强度上限 3 ]
       [ 段2: 场景B × 4 分钟 · 语音 sequenceB · 强度上限 2 ]   ← 可选
       [ 段3: 场景A × 3 分钟 · 语音 close      · 强度上限 1 ]   ← 可选
```

- **患者只按一次**（会话开始时确认），后续全部由技术员控制。
- 技术员手上永远有三个动作：`下一段`、`结束本次`、`重新校准`；段的推进可以手动，也可以到时自动（默认自动推进，可关）。
- 平板上常驻一条**流程带**：`第 2/3 段 · 仰望湖面 · 还剩 03:12`，下一段是什么一眼可见。
- 会话时长 = 各段之和；到点自动进入下一段，最后一段结束即会话结束（同样走淡出）。

## 3 校准：显式、可重做

**改成显式触发**，这是现场"说不清"的根源。

| 时机 | 行为 |
| --- | --- |
| 进入准备间 | 患者按下确认后，头显显示一张卡：**"请保持现在的姿势，技术员开始记录"**，技术员在平板上点 `记录起始体位` |
| 记录中 | 卡面显示倒计时（现有 1.8 s 稳定窗 + 3 s 计数），并注明"请患者保持不动" |
| 完成后 | 卡面显示"已记录"，场景列表在平板上解锁；技术员选择并进入正式场景 |
| 会话中 | 校准可随时重做：`重新校准` 不结束会话，只重跑一次记录；会话时钟、峰值与段落继续累计 |
| 段与段之间 | **不重新校准**，只换内容（`switchSceneLive` 保证朝向连续） |

技术员不需要理解"为什么突然校准了"——因为校准只在**他按下那个键**时发生；V1 的自动触发已经不存在。

## 4 控制性：谁能动什么

| 动作 | 患者 | 技术员 |
| --- | --- | --- |
| 进入准备间 | 按一次确认 | 启动（页面入口）并引导患者 |
| 校准 | 保持不动 | 记录起始体位 / 重新校准（随时） |
| 进入正式场景 | — | 标定后选卡，再按 `进入正式场景` |
| 切段 | — | 下一段（可提前） |
| 强度 | — | 0–3，受当前段上限约束 |
| 语音 | — | 逐句 / 连续播放 / 停止 |
| 结束 | 口头说停 | 结束本次 |

**规则**：患者只有一次交互；技术员的所有动作都在会话内即时生效，不需要二次确认，除了 `结束本次`（可撤销性低，保留一次确认——与现在的行为一致）。

## 5 头显侧的入口：让窗口自己出现在面前

现状：每次都要人手在 FxR 里点一次"进入 VR"，窗口还可能出现偏在一侧。

做法（按可行性排序）：

1. **页面侧**：进入会话时，页面在 `requestSession` 之后立即把 2D 窗口的朝向对齐到患者当前视线；FxR 若不支持，则在首帧里用一次 `view:anim:recenter` 把视线拉回正中。
2. **头显壳**（Android）：`PortalActivity` 拉起 FxR 时带上前台 Intent，让页面在启动时已处于"面向正前方"的窗口姿态；这一步今天已经有 `EntryRetry`，只差窗口姿态。
3. **注入点击**（已有 `TapService`）：FxR 需要一次真实手势才能进沉浸模式，用无障碍注入一次点击代替患者按——这条已实现，但只在真机验证过"能注入"，未验证"落在 2D 面板上"。

目标是：**患者戴上就能看到画面**，只有"开始"这一次需要他按（而这一次是设计上的确认，不是技术妥协）。

## 6 落地顺序

| 步 | 内容 | 状态 |
| --- | --- | --- |
| 0 | 内置准备间 + 场景列表在 XR 与标定后解锁 + 选卡与 `进入/切换` 两步 | ✅ 本轮 |
| 1 | 校准显式化（§3），页面 + 平板文案 | ✅ `18b1e34`；会话中重校准本轮补齐 |
| 2 | 段的编排：平板 `SessionProgram`（段列表、时长、语音、强度上限），`program:` 一次下发；页面自动推进并回传段进度；台账按段记录 | ✅ 本轮 |
| 3 | 过渡与朝向（§5 第 1、2 条）；段间淡出复用结束淡出 | ⬜ 需真机 |

## 7 未决（需要产品定）

1. 段间是否**强制**留 5 秒"过渡段"（画面淡出 → 淡入下一段），还是硬切但提示"即将切换"？
2. 会话结束后是否自动归档一份**段落记录**（每段时长、用到的场景）进会话台账？
3. 默认模板给谁：技术员每次手配，还是预设"三场景 15 分钟"这类模板？
4. 一段里能不能换强度上限：段声明上限，会话中技术员只能往下调？
