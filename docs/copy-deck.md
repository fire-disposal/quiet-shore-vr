# 文案对照表（患者侧 / 技术员侧）

状态：2026-11-12，随 0.9.x VR 内界面收敛（strings / 空间 HUD / 字幕条 / SUS 卡）。整体说法见 `docs/introduction.md`，两者冲突时界面短句服从本表。新增或修改任何界面文案、语音文本前，先在此表登记。

## 1 术语决定

| 概念 | 患者侧叫法 | 技术员侧叫法 | 不用 |
| --- | --- | --- | --- |
| 整个流程 | 体验 | 训练 / 会话 | 治疗、疗程 |
| 操作设备的人 | **工作人员** | 技术员 | 医生、操作员 |
| 记录起始体位 | 记录体位 / 体位已记录 | 校准 | 标定、对齐、校准算法 |
| 立即停止 | 停下 | 急停 | 中止 |
| 计划内结束 | （患者不操作） | 结束 | 停止、退出 |
| 背景音 | 水声 | 水声 / 环境声 | 白噪音 |
| 语速/幅度 | 起伏 | 强度、档位 | 音量（那是另一项） |
| 场景 | 洁净立便间 / 仰望湖面 / 光井 | 同左 | 洗手间、湖景 |
| 正在运行 | 头显 | 头显 / XR | 沉浸模式、WebXR、VR 模式 |
| 头显与平板之间的连接 | （不出现） | 控制端 / 平板 | 蓝牙、BLE、协议 |

规则：患者侧第二人称一律"您"；一句一个事实，一句 ≤ 20 字；不评价、不许诺、不催促；技术员侧用动词开头（启动、结束、校准）。

### 1.1 两侧语域（2026-11-12 起）

两侧的读者不同，口吻也不同。不要拿同一套话两头套。

**患者侧**——VR 入口页、记录体位卡片、字幕条、SUS 题面与致谢、纸质告知单。读者是普通患者。

- 用词准，但不刻意通俗。不写"咱们""别急""放心吧""很简单"。
- 不用比喻去解释医学或系统概念。不哄、不劝、不承诺。
- 不解释常识。"戴上头显就能看到画面"这类句子删掉。
- 只写患者此刻要做的动作，和此刻发生的事实。
- 内部术语照旧不用：WebXR、BLE、协议、状态帧、校准算法。

**控制侧**——平板应用、头显控制台 APK、操作手册。读者是医务人员。

- 专业术语与缩写直接用，不解释：BLE、会话、体位、记录、SUS、强度档、接管。
- 句子更短。动作动词开头。去掉客套与铺垫。
- 错误文案写"原因 + 下一步"，不写安抚。

| 侧 | 反例 | 改为 |
| --- | --- | --- |
| 患者侧 | 戴上头显就能看到画面 | 按一下头显右侧的按钮 |
| 患者侧 | 别急，慢慢来 | 保持现在的姿势 |
| 控制侧 | 头显好像没有连上，麻烦您检查一下 | 头显未连接。回配对页重连。 |
| 控制侧 | 现在正在记录体位，暂时不能切换 | 记录体位中，切换被拒绝。稍后再切。 |

**患者侧不得出现的词**：WebXR、沉浸模式、BLE、蓝牙、协议、校准算法、SUS、draw call、三角面、FPS。这些只出现在诊断 HUD 与平板控制端，且 HUD 默认关闭。

## 5 每轮改动的检查项

1. 新文案是否出现在本表（没登记就不合入）。
2. 同一动作在患者侧与技术员侧是否用了各自规定的词。
3. 是否引入了评价、承诺、催促或精确数值。
4. 语音文本与界面用词是否一致（"校准"不出现在患者侧语音里）。
5. 两侧语域是否分开（见 §1.1）：患者侧不哄不劝不解释常识，控制侧术语直接用。

| 接管 / 正在接管 / 已接管 | 控制权、释放控制 |
| 校准 / 校准中 | 记录体位（技术员侧）、标定 |
| 体位；视高；起伏；强度 | 身体、姿态、眼高、音量（指强度时） |
| 朝向；偏航；俯仰 | 姿态（读数标题） |
| 语音提示；连续播放；声音；水声 | 台词、序列、混音 |
| 打开量表；关闭量表；归档；导出 | 在头显中打开、分享目标 |
| 训练页 | 训练页面、页面没开 |
| 等待按压（阶段短签）；等待患者确认（说明） | 等待确认（作按钮） |

**专业词的使用边界**：控制侧读者是医务人员，术语可以直接用（第 1 节已定），但界面句子里
不出现实现细节——`BLE`、`state`、`帧`、`协议`、`band`、`mix` 一律换成上表里的界面词；
只有在“两端版本不一致”这类确实需要指向实现层的错误里，才写「头显应用需要更新」。

**一句只说一件事**：按钮 ≤4 字，状态句 ≤12 字，错误句 = 原因 + 下一步。
**形状语言**：实心 = 可按（急停红实心、会话主行动冰实心，每屏至多一个）；描边/冰色左条 = 当前状态。

## 8 空态、提示与警告：句式与体量

控制端的提示文字只有一个读者—— bedside 的技术员，读的时候手里还拿着平板。所以句式
固定、体量封顶、不写解释性长句。**语气与第 1 节一致**：动词开头、不客套、不哄。

### 8.1 四种句式

| 场景 | 句式 | 例子 |
| --- | --- | --- |
| 空态 | `<对象>未<状态>` + 至多一行原因 | `镜像未连接` / `头显未连接，或未收到状态帧` |
| 进行中 | `正在<动词>` | `正在搜索` / `正在重连` / `正在结束` |
| 阻塞 | `<原因>，<下一步>` | `校准中，仅急停可用` |
| 故障 | `<现象>。<动作>` | `头显未回应。保持开机，等待重连。` |

### 8.2 体量

- 空态：**标题 ≤8 字 + 解释 ≤20 字，且解释只允许一行**。要给出动作就用按钮，不要写第二行句子。
- 提示行（顶栏下、面板内）：一行，≤20 字，不折行；折行说明该降级成空态或删掉。
- 警告：≤24 字，写成「现象 + 动作」；不写原因分析、不写"可能"。

### 8.3 一致性

- 同一状态只有一种写法：`未连接` 不写成 `断开连接`/`没有连上`；`正在重连` 不写 `重连中`。
- 不在正文重复顶栏已说的状态（顶栏写着 `已连接`，正文不必再说“连接正常”）。
- 不用第二人称；不用"请"两次以上；无感叹号；无省略号；数字用阿拉伯数字。
- 括号只用于单位与限定（`（20 秒）`），不用括号塞解释。

### 8.4 与界面风格的关系

- 空态是**没有内容**，不是错误：用次级墨 + 分区同构（标题 + 发丝线），不加图标、不加底色、不用强调色。
- 警告是**有内容但要注意**：行内文字 + 左侧 2dp 次级竖线；只有「需要立刻停止」才允许红，而红在全系统只属于 `急停`。
- 按钮只有一种填充语义（见第 7 节）：空态里若无可执行动作，就不出现按钮。
