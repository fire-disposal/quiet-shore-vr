- 范围：WebXR 生命周期、运动与音频，平板 BLE 与持久化，头显 GATT、WS 与入口监督。
- 方法：三个只读子代理分片审查，主会话复核代码路径，并对四个核心边界运行独立最小复现。

## 高优先级

### H1：WS 首次断链可能直接刷新页面

- 位置：`src/app/portal-link.ts:222,367-399`
- 证据：`lastOpenAt` 初始化为 0，全文件没有写入。页面运行约 30 秒后，任意一次 socket 关闭都可能进入自愈刷新分支，200 ms 后执行 `window.location.reload()`。
- 影响：短暂回环服务抖动会刷新患者页面，中断 XR，并丢失内存中的问卷状态。
- 验证：静态。
- 修复：记录本次持续断链时长，只在连续断链超过阈值后刷新，不复用页面运行时间。

### H2：停止命令之后仍会执行旧运动命令

- 位置：`android/control/src/main/kotlin/com/quietshore/control/ble/CommandQueue.kt:34-60`
- 证据：停止命令只清除 `move`，不会清除 `discrete` 中更早的 `posture:rise`、`posture:lower` 或视角动画。`poll()` 先返回 stop，下一次又返回旧运动命令。
- 影响：患者侧先冻结，随后又继续运动，违背最后一次停止操作。
- 验证：静态。
- 修复：停止命令入队时清除同通道中更早且已被停止语义超越的命令，停止之后的新命令仍须保留。

### H3：延迟切场会越过停止和退出

- 位置：`src/app/App.ts:1159-1247`
- 证据：停止态检查发生在安排切场之前。实际切场延迟 220 ms，定时器无取消、无 generation，回调内不重新校验生命周期。
- 影响：停止后仍可能换场、重开音频、写 `scene.switched`，不同静止姿态的场景还可能重新启动姿态斜坡。
- 验证：静态。
- 修复：停止、退出和 dispose 时取消定时器，回调执行前校验 generation 与生命周期。

### H4：首次校准等待态允许应用切换并遗留训练状态

- 位置：`src/app/App.ts:856-898,1641-1665,2127-2150`
- 证据：生命周期已为 `calibrating`，但等待技术员期间 `capturePending=false`。应用切换只拒绝运行中和正在采样的校准，因此可切入问卷并保留 `awaitingCalibration` 与校准卡。
- 影响：校准卡与问卷同时出现，患者确认会在问卷应用中启动训练校准，后续应用切换被运行态拒绝。
- 验证：静态。
- 修复：应用切换要求整个生命周期为 `idle`，或先完整取消等待校准及其界面、输入层和世界冻结状态。

### H5：WS 注册与 since 重放存在实时命令插队窗口

- 位置：`android/headset/src/main/kotlin/com/quietshore/portal/PortalService.kt:550-580,821-826,1149-1150`
- 证据：sink 先加入 `wsSinks`，writer 启动后才执行 `sendGapFill`。实时 seq 3 可在历史 seq 1、2 之前入队，形成 `ready,3,1,2,3`。
- 影响：页面按最新水位去重时可能丢弃历史命令；先 ACK 3 还可能清除保留区中的 1、2，使其无法再次恢复。
- 验证：静态竞态。
- 修复：原子完成 ready、pending 快照和 gap-fill 入队，再将 sink 暴露给实时广播。

### H6：自动点按持续失败会永久绕过 relaunch 和 GIVE_UP

- 位置：`android/headset/src/main/kotlin/com/quietshore/portal/EntryRetry.kt:105-138`
- 证据：deadline 返回 TAP 后设置 `tapped=true`，`tapFailed()` 又设回 false。只要自动点按持续失败，每次 deadline 都重新进入 TAP，`retries++` 不可达。
- 影响：入口无限停留在确认页，既不会重新拉起浏览器，也不会进入人工处置状态。
- 验证：静态。
- 修复：分别记录补试次数和本次 launch 的点按额度，补试耗尽后必须进入 RELAUNCH。

### H7：重复 HELLO 清空命令去重窗口

- 位置：`android/headset/src/main/kotlin/com/quietshore/portal/BluetoothControl.kt:698-713,773-787`
- 证据：同一控制者每次 HELLO 都执行 `seqResults.clear()`。WELCOME 丢失后的握手重试会删除既有 seq 的 ACK 记录。
- 影响：相同 seq 的非幂等命令可再次执行，例如环境声被重复切换。
- 验证：静态。
- 修复：只在获得新控制者时重置 seq 窗口，同一地址重复 HELLO 不得清空记录。

### H8：3 秒校准窗口只统计前 64 帧

- 位置：`src/core/xr/calibration-sample.ts:83-108`，调用配置位于 `src/app/calibration-run.ts:40-47`
- 证据：达到容量后直接忽略后续样本。60 Hz 和 72 Hz 下分别只覆盖前约 1.07 秒和 0.89 秒。
- 影响：后段缓慢头部偏移不进入均值和离散度，校准可能采用旧朝向并接受本应拒绝的窗口。
- 验证：已复现。3 秒、60 Hz、后约 1 秒偏移 10°，结果为 `samples=64, ok=true, meanX=0`。
- 修复：容量覆盖完整窗口，先采用适合 PICO 3 秒采样的 256，并增加后段漂移回归测试。

### H9：回正在特定交接时继续执行旧俯仰动画

- 位置：`src/core/xr/view-motion.ts:301-330`
- 证据：旧上仰动画尚未推进时执行回正，若偏航仍需回正，无新俯仰段的分支不会清除旧 `pitch.timed`。
- 影响：俯仰继续上仰而非回零，状态目标也被旧段改成旧终点。
- 验证：已复现。执行回正 1.5 秒后 `upGazeDeg=5`，`targetUpGazeDeg=10`。
- 修复：无新俯仰段时也清除旧俯仰段，并显式将俯仰目标设为回正目标。

### H10：旧 BLE 写回调可以污染新连接写状态

- 位置：`android/control/src/main/kotlin/com/quietshore/control/ble/BleController.kt:474-509,599-607`
- 证据：断链将 `writing=false` 且 `nextSeq=0`。旧请求延迟完成时无条件清除 `writing`，失败回调还按 seq 删除 `inFlight`，没有连接或写 token 校验。
- 影响：新连接可能出现并发 GATT 写，同序号的新 ACK 记录可能被旧回调删除，ACK 随后被当成未知 ACK。
- 验证：静态竞态。
- 修复：每次连接和写入分配 generation/token，旧回调不得修改新连接状态或触发新连接的 pump。

## 中优先级

### M1：第二次及第三次自动重连只扫描，不连接

- 位置：`android/control/src/main/kotlin/com/quietshore/control/ble/BleController.kt:128-157,246-260`
- 证据：第一次重连后分支改为 `autoScan=true` 并扫描，扫描回调只上报结果，明确不调用连接。
- 影响：第一次直连重试失败后，后续两次退避无法恢复链路。
- 验证：静态。
- 修复：内部恢复流程继续连接已选择的 `lastAddress`，不要切换到只报告结果的人工扫描。

### M2：默认 MTU 下合法的较大文档会抛异常并断开 WS

- 位置：`android/protocol/src/main/kotlin/com/quietshore/control/protocol/ControlProtocol.kt:564-572`，`android/headset/src/main/kotlin/com/quietshore/portal/PortalService.kt:718-789`
- 证据：默认 MTU 23 时每块 payload 为 17 字节，255 块上限对应 4335 字节。超限由 `require` 抛出 `IllegalArgumentException`，WS 边界没有对应处理。
- 影响：较大目录、问卷或会话记录可导致控制通道反复断线，目录更新还可能先产生本地副作用。
- 验证：静态边界计算。
- 修复：统一 WS 与 JSON 通道尺寸契约，在副作用前检查尺寸，以明确的协议关闭代替异常逃逸。

### M3：MTU 跨控制者、断链和蓝牙重启残留

- 位置：`android/headset/src/main/kotlin/com/quietshore/portal/BluetoothControl.kt:140,425-459,501-507,887-888`
- 证据：全局 `mtu` 在 teardown 时不恢复 23，任何连接设备的 `onMtuChanged` 都能修改当前分块尺寸。
- 影响：新链路协商失败时可能按旧 MTU 517 分块，导致通知超限；非控制者也能干扰当前控制者。
- 验证：静态状态残留，具体通知表现依赖 Android 蓝牙栈。
- 修复：teardown 时恢复 23，并按设备保存 MTU，只使用当前控制者的值。

### M4：SUS 订阅补发绕过 JSON 分帧和控制者过滤

- 位置：`android/headset/src/main/kotlin/com/quietshore/portal/BluetoothControl.kt:491-507,960-985`
- 证据：CCCD 订阅路径直接发送缓存的裸 SUS JSON，没有正常 envelope 和三字节分块头，也没有 `isController` 检查。
- 影响：平板无法按 JSON 通道正常重组补发记录，长记录还可能超过 ATT MTU，非控制者也能取得缓存答卷。
- 验证：静态。
- 修复：补发复用正常 SUS envelope、分帧、MTU 和控制者过滤。

### M5：HTMLAudio 回退在实际播放前误报成功

- 位置：`src/audio/voice.ts:301-376,380-432`
- 证据：`playWithElement()` 调用 `audio.play()` 后立即返回 true，未等待接受或拒绝。序列据此排定后续计时。
- 影响：实际播放被拒绝时，接口仍返回成功，序列保持活动并在静音中推进。
- 验证：已复现。实际错误为“播放被拒绝”，但 `play()` 返回 true，序列仍排定 21 秒后的下一句。
- 修复：回退等待播放结果，拒绝时返回 false，并用音频实例身份保护异步回调。

### M6：断链期间产生的会话摘要和事件永久丢失

- 位置：`src/app/portal-link.ts:535-540`，`src/app/App.ts:946-970`
- 证据：socket 非 OPEN 时 `send()` 直接返回。断链停止路径随后生成的 session 和 log 必然被丢弃，重连只补状态和目录。
- 影响：最容易缺记录的恰恰是断链终止的会话，SUS 和一次性行为事件也无法恢复。
- 验证：静态。
- 修复：为 session、SUS 和关键事件建立带 ACK 的持久 outbox，连接恢复后补发。

### M7：SUS 重连补发被重复持久化

- 位置：`android/control/src/main/kotlin/com/quietshore/control/ControlViewModel.kt:901-925`，`android/control/src/main/kotlin/com/quietshore/control/data/SusStore.kt:23-26`
- 证据：协议要求订阅时补发最后一帧，`handleSus()` 无条件 append，存储没有去重。
- 影响：同一答卷在历史和导出中重复计数，事件日志重复，重复项还会挤占最近 50 份中的真实记录。
- 验证：静态。
- 修复：按稳定记录键去重，仅实际新增时追加事件和显示已记录提示。

### M8：SUS 答案和面板跨会话复用

- 位置：`src/app/App.ts:1011-1067,1532-1546`
- 证据：面板与 `susAnswers` 是页面级单例，会话结束只关闭面板，不清空答案或重置面板内部状态。
- 影响：不刷新页面开始下一位患者时仍携带旧答案，后续修改或关闭会把旧答案计入新记录。
- 验证：静态。
- 修复：增加明确的新答卷边界，同时重置 App 答案数组和缓存面板状态，普通 close/reopen 仍保留同一份答卷的暂续能力。

## 低优先级

### L1：斜坡端点立即反向会被误判为无需操作

- 位置：`src/app/world-runtime.ts:276-294`
- 证据：`rise()` 只比较 `next === mix`。斜坡刚开始且 mix 仍在端点时，立即反向会直接返回，不改变旧 target。
- 影响：操作员快速反向时，世界仍朝旧方向运动。
- 验证：已复现。`rise(1)` 后立即 `rise(0)`，状态仍为 `target=1, moving=true`。
- 修复：无操作判断同时考虑当前 target 和 moving，正在离开请求目标时必须重新建立反向斜坡。
