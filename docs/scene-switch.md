# 会话中切换场景：现状与重设计

状态：2026-11-12（当日改判）。**会话中切场景已开放**：页面侧的 `switchSceneLive` 早就实现了，
本次只是把平板界面上的锁打开，并让读数、镜像、强度上限都随状态帧更新。

仍待设计的是第 2、3 节里的过渡与朝向连续性——现在切换是硬切，世界在一帧内换掉；
这是已知缺陷，不是"不能做"。第 4 节的验收在过渡设计落地时执行。

## 1 现在已经能跑的部分

`src/app/App.ts` 的 `applySceneCommand` 对运行中的会话不做拦截，走 `switchSceneLive`：

- 只换世界内容：校准帧、视线偏移、起伏播放器都保留，患者不用重新对准。
- 强度上限按新场景夹紧（`floating.setLevel(previousLevel, this.sceneComfortLevel)`），包络自己缓降，不跳变。
- 若新场景的构图对应不同体位（`sceneRestMix` 变了），世界按操作员平时的斜坡升到新值，并把起伏的相位清零——否则升降轴会带着旧世界的运动转过去。
- 音频床随场景换（`stopSceneAudio` → `startSceneAudio`）。
- 状态帧立即重发，平板读数跟着换。

协议层 `scene:<id>` 在会话中**是接受的**（`ControlProtocol.SCENE_PREFIX` 上的旧注释写“只在会话前生效”，是错的，本轮已改）。平板只是没有把入口放出来。

## 2 为什么还不能交付

“换一张图”不等于“换一个场景”。一次会话中换场景，患者正在经历的是：

| 问题 | 现状 |
| --- | --- |
| 视觉过渡 | 硬切。结束流程有淡出，切换没有；全黑闪一下，或世界在一帧内换掉 |
| 朝向连续性 | 世界换了，患者的偏航/俯仰不变——但两个场景的“正面”未必同向，患者可能忽然面朝墙 |
| 体位构图差 | 场景按不同眼高/姿态构图，切换时 `restMix` 变化会带一次斜坡，患者不知道身体为什么在动 |
| 声音 | 水床被直接换掉，没有淡入淡出，也没有在语音播放中途换场时的规则 |
| 操作员心智 | 一次点击就换场，代价不可见；换错了要再点一次才回来，中间没有确认或撤销 |
| 校准 | 校准帧保留是对的，但换场后是否需要一次“回正”提示，没有定论 |
| 记录 | 状态帧里只有一个 `scene`，一场会话跨两个场景时，台账/归档记哪个？ |

## 3 重设计要定的事

1. **过渡形态**：淡出→换世界→淡入（与结束同一条曲线），还是保留长黑？时长要不要随患者状态变？
2. **朝向对齐**：换场时是否把患者当前视线方向映射到新场景的“正面”，还是保持绝对朝向、只换内容？
3. **体位差**：不同 `restMix` 的场景之间切换，先回到一致姿态再换，还是允许斜坡带着过渡？
4. **音频**：场景音床交叉淡入淡出；语音正在播时的规则（继续、暂停、还是等这句读完）。
5. **操作面**：单点即换，还是“长按/二次确认”？换场是否要能撤销（回到上一个场景）？
6. **记录**：一场会话跨场景时，台账与 SUS 记主场景还是按时间段记。
7. **失败路径**：换场时连接中断、正在结束、记录体位中——现在的拒绝文案要统一到 `copy-deck` 的措辞。

## 4 验收（落地时按这个测）

- 患者不重新对准：换场后偏航/俯仰读数连续，无跳变。
- 强度不越界：从高档场景换到低档场景，读数在包络内缓降，不出现一次台阶。
- 过渡无全黑硬闪；音频无爆音、无重叠。
- 平板在换场瞬间的界面状态与头显一致（不出现“已切”而头显仍在旧场景）。
- 一场跨两场景的会话，台账里能读出“在哪个场景用了多久”。
