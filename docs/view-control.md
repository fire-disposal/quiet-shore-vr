# 镜头/动画控制范式

状态：设计稿（2026-10-24）。对象是"操作员让患者视角/场景动起来"这条链路：平板 → BLE → 头显服务 → 页面 → 渲染。

## 1 现状

| 环节 | 现在的做法 |
| --- | --- |
| 连续朝向 | `view:orient:<yaw>,<pitch>` 绝对角度，Write Without Response，≤10 Hz，无 ACK、无时间戳 |
| 预设动画 | `view:anim:up\|down\|recenter\|breathe`，离散、带 ACK、固定曲线与时长 |
| 停止 | `view:stop`，立即冻结、不回正 |
| 回读 | state 5 Hz，v11 带 `tMs/seq` |

页面侧已经有编排能力：二阶阻尼、15/30 °/s 上限、60 °/s² 加速度限幅、预设用 smootherstep。**问题不在动画，在指令的形状。**

## 2 为什么"发绝对量"不聪明

| 问题 | 后果 |
| --- | --- |
| BLE 没有时间戳 | 接收抖动直接变成运动抖动，10 Hz 的滑杆在 72 Hz 的屏幕上永远在追半步 |
| Write Without Response 会丢 | 丢一帧，下一个绝对量就是阶跃；而阶跃正是要避免的东西 |
| 绝对量跨坐标系 | 平板想表达"转到某个角度"，患者看到的是"世界相对眼睛怎么转"；中间还夹着校准与舒适层 |
| 频率即成本 | 10 Hz × 2 个角度值占连接事件，却只表达了"操作员的手在哪儿"这一条信息 |
| 多来源互相覆盖 | 将来若有自动编排或语音驱动，两条绝对量会在同一帧打架 |

一句话：**平板不该逐帧描述结果，只该描述意图。**

## 3 范式：意图 + 本地编排

```text
平板（意图）                头显页面（编排）              渲染（表现）
rate / goto / preset  ──►  曲线、限速、租约、夹紧  ──►  每帧读一次
stop / 安全停止       ──►  最高优先级              ──►  立即冻结
```

三条规则：

1. **绝对角度只允许一次性 `goto`**：带目标、时长与 ACK，页面负责曲线与限速。
2. **连续控制用速率**：`rate` 表示"这一秒想往哪边转多快"，带 300 ms 租约；租约到期按 60 °/s² 减速到停。丢包不会造成阶跃——只是少刷新一次意图。
3. **平板不做动画、不推算角度**：界面只显示回读（v11 的 `viewPitch/viewYaw/tMs`）。所有夹紧、限速、停止只在页面执行一次。

优先级固定：`stop` / 安全停止 > `goto` / `preset` > `rate`。任何更高优先级的命令到达，低优先级的租约立即作废。

## 4 契约

| 命令 | 参数 | ACK | 语义 |
| --- | --- | --- | --- |
| `view:rate:<yaw>,<pitch>` | 度/秒，yaw ±45、pitch ±20 | 否 | 持续意图，TTL 300 ms；页面累加进目标并夹紧 |
| `view:goto:<yaw>,<pitch>,<ms>` | 目标角、时长 200–4000 ms | 是 | 一次性，带零首末速曲线 |
| `view:anim:<preset>` | up/down/recenter/breathe | 是 | 现有预设，曲线固定在页面 |
| `view:stop` | — | 否 | 立即冻结，不回正 |
| `view:orient:<yaw>,<pitch>` | — | 否 | **保留一个版本周期**，内部折算为 `goto(…, 800 ms)`，随后删除 |

`rate` 与 `goto` 都走同一套页面实现（二阶阻尼 + 加速度限幅 + 上限），所以两条路径的手感一致。

## 5 延迟预算

| 段 | 量级 |
| --- | --- |
| BLE 写（含连接间隔） | 7.5–30 ms |
| 服务转发到页面 | ≤1 帧（16.7 ms） |
| 页面应用（下一帧） | ≤16.7 ms |
| 合计（操作→可见） | **≤80 ms** |

80 ms 对"缓慢治疗性运动"是安全余量：人手感知的"同步"阈值约 100–150 ms。抖动由 60 °/s² 的渐入吸收，不靠平板端插值。

丢包与断链：

- `rate`：丢 1–2 帧无感；连续丢 → 300 ms 后自动减速停下（患者不会看到失控）。
- `goto` / `preset`：ACK 驱动，超时重试一次，失败则报错而非静默。
- 断链：页面在 lease 到期或 `link-lost` 时冻结；两条路径都收敛到同一停止语义。

## 6 在何处执行

| 环节 | 执行处 | 理由 |
| --- | --- | --- |
| 意图与界面 | 平板 | 操作员的手在那儿 |
| 曲线、时长、速度/加速度限幅、租约 | 头显页面 | 只有它知道帧时钟与患者头部状态；安全不能依赖链路 |
| 命令白名单与语义校验 | 协议库 + 头显服务 | 单一校验点 |
| 镜像再现 | 平板渲染 | 只读，不作权威；用 v11 的已应用值 |

## 7 迁移顺序

1. 协议加 `view:rate` 与 `view:goto`；`view:orient` 标记为内部折算。
2. 页面：`rate` 累加 + 租约计时（300 ms 无刷新即减速）；`goto` 复用现有段动画。
3. 平板：未来的镜头面板只做"按住 → rate / 点按 → goto"，松手即停止刷新意图，不发绝对值。
4. 回读保持 v11：操作员看到的一直是"已应用"，不是"已发送"。
5. 一个版本周期后删除 `view:orient`。

## 8 验收

| 项 | 目标 |
| --- | --- |
| 操作到可见 | ≤80 ms（P95，同一房间） |
| 松手到静止 | ≤700 ms（60 °/s² 减速） |
| 丢 10% 包 | 无可感知阶跃（A/B 自测：录屏逐帧看角增量） |
| 单帧角增量 | ≤ 上限 × dt，不反号 |
| 断链 | 冻结 ≤300 ms，错误可见 |
| 幂等 | `goto` 重发不叠加位移（同 seq 去重） |
