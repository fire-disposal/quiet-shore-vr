# v2 代码架构：精简什么、补什么

状态：2026-11-12。动机是 v1 → v2 这次迭代：界面重做已经动了控制端的结构，场景流程加长
（`docs/v2-roadmap.md`）又要动场景契约，趁着两头都在改，把结构性的欠账一次结清，避免
v2 之后再付一遍迁移成本。

原则：**先删后加**。任何一项改动都要能说清“删掉了什么重复/空白”，不只是“分层更漂亮”。

## 1 现状体量（2026-11-12 实测）

| 面 | 行数 | 最大文件 |
| --- | --- | --- |
| 页面（TypeScript） | 14 311 | `src/app/App.ts` 1 958 |
| 安卓（Kotlin） | 12 524 | `PortalService.kt` 1 639；`BluetoothControl.kt` 1 013；`PortalActivity.kt` 952 |

五个文件占了安卓端的一半以上，其中三个在头显进程里。这不是“文件大就要拆”，而是
**它们各自混了两三种职责**，拆的时候要连着职责一起拆。

## 2 该做的（按性价比）

### 2.1 控制端：一份状态，两个身份

`ControlUiState` 现在同时装着「从状态帧读到的镜像」和「操作员本地的意图」（对话框开没开、
待确认的动作、SUS 面板的滚动位置）。后果是远端每帧合并时都要小心翼翼地跳过本地字段
（`RemoteMerge.kt` 里的规则就是在补这个洞）。

改法：`RemoteState`（只由状态帧写）+ `LocalUi`（只由界面写）+ `UiState = combine`。
验收：`RemoteMerge` 的合并规则消失，`ControlViewModel` 少一层字段白名单；真机跑一次
「另一台平板接管」的路径，确认没有本地状态被远端覆盖。

### 2.2 头显端：命令面只有一份

页面已经有 `commands.ts`（`enter` / `stop` / `scene:` / …），头显侧又用散落的 `when` 重复
了一遍；两边一改就会出现“平板能发、头显不认”。协议里 `CAPABILITIES` 已经是唯一清单。

改法：`sealed Command` + `CommandRouter`，由 `CAPABILITIES` 生成测试用例；`ControlChannelCheck`
里那 422 行的握手脚本改成对 `CommandRouter` 的表驱动测试。
验收：新增一条命令时，只需改 `ControlProtocol` 与页面，头显侧由编译错误逼着补上。

注：这一项要实机回归（BLE 通路），排在界面合并之后。

### 2.3 头显端：把 `PortalService` 里的三件事分开

1 639 行里混着：BLE 外设的生命周期、静态页服务（`127.0.0.1:8130`）、以及“拉起 Firefox
Reality / 退到后台 / HOME 键”的 Intent 编排。三者都重要，但只有第三件会在会话中出事。

改法：`PageServer`（本地静态服务）、`Foreground`（Intent 编排 + 常驻通知）、`PortalService`
只保留 BLE 与生命周期；`EntryRetry` 与 `TapService` 仍独立。
验收：`onDestroy` 之后没有残留的通知与页面服务；断链重连 30 次不泄漏。

### 2.4 场景契约：为时间线预留，而不是现在就加

`docs/v2-roadmap.md` 的 `phases` 会改 `SceneDefinition`。这一项**不要**和界面合并混在一个
提交里；先定接口（可选字段），四个场景里只让 `shore` 先用上，其余保持 `undefined`，
避免一次改动四个场景的画面。

### 2.5 文档去重

- `docs/state-v11.md` 描述的是 v11 帧，当前是 v14；改成“历史”或在标题里写死 v11，别让人当现状读。
- `docs/copy-deck.md` 第 1 节（术语）与第 7 节（v2 界面词）有重叠：第 1 节制患者侧，第 7 节制
  控制端，各自标注适用范围，冲突时以第 7 节为准（控制端）。
- `docs/ux-plan.md` 的旧观察已在 TODO 里标过时，直接删掉过时段落，别留“已标注过时”的注释。

## 3 不该现在做的

| 项 | 为什么 |
| --- | --- |
| 拆 `App.ts` | 1 958 行确实大，但它现在正在被界面与场景两条线同时触碰；等场景契约定了再拆，否则拆完还要再动 |
| 换状态库（Compose / 页面） | 现有状态机是显式且可测的，换库等于把测试重写一遍，收益不成立 |
| 合并两端的 `Command` 类型 | 跨语言（Kotlin / TS）合并只能靠生成代码，收益低于维护生成器 |

## 4 顺序

1. 界面合并 → v2.0.0（进行中）。
2. 2.1 控制端状态分层（只影响平板，模拟器可验）。
3. 2.5 文档去重（无风险）。
4. 2.2 命令面 + 2.3 `PortalService` 拆分（要实机，安排在一起做一轮回归）。
5. 2.4 场景时间线（与 `shore` 样板一起）。
