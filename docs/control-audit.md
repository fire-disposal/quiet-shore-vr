# 控制端审查：逻辑完整性、可培训性

状态：分析稿（2026-10-24）。对象是平板 `com.quietshore.control` 与它依赖的 v11 链路；场景侧（第三个场景）不在本文范围。

## 1 控制端现在是什么

| 层 | 现状 |
| --- | --- |
| 配对 | 冷启动 → 手动扫描 → 匹配服务 UUID/名称的第一台自动连接 → `CLAIM` 接管 |
| 会话 | 启动 / 结束 / 急停 / 重新校准 / 退出场景 / 退出系统 |
| 体验 | 模式（漂浮/起身）、强度 0–3、档位 a/b/c、呼吸层、颗粒、起身升降 |
| 评估 | SUS 打开/关闭、目视选择开关 |
| 观察 | 镜像（3D 复现）、状态面板、角度表 |
| 语音 | 抽屉：序列、单句、音色、混音（新） |

顶栏 6 个入口（状态/场景/镜像/语音/面板/断开），两个抽屉，一个可折叠 rail。

## 2 逻辑缺口

| # | 现象 | 证据 | 影响 | 修法 |
| --- | --- | --- | --- | --- |
| C1 | **没有"等待患者确认"态**：`enterTraining()` 只发 `enter`，`sessionActive` 在 `onControlGranted` 就置 true（那是"已接管"，不是"在训练"） | `ControlViewModel.kt:177-179`、`:343-352` | 启动后屏幕仍显示"待机"，按钮仍可点，操作员重复点击、重复拉起页面 | 新增 `startPending`（20 s 超时/会话开始即清），按钮置灰并显示"等待患者确认" |
| C2 | **校准相不可见**：v11 帧有 `calibrating`，平板没有任何显示 | `ControlProtocol` bit1；`ControlPanel`/`StatusPanel` 均未引用 | 技术上最需要口头配合的 30 秒里，屏幕写着"待机" | 会话标题按 `control.calibrating` 显示"校准中 · 请患者平视前方" |
| C3 | **结束与急停是同一条命令** | `endSession()` 与 `emergencyStop()` 都发 `stop` | 两个名字一个行为，稀释"急停"的紧迫性 | 保留一个"结束"；急停改成独立、常驻、走 `stop` 且 400 ms 内确认已生效 |
| C4 | **强度仍是 0–3** | `setFloatLevel()` 夹紧 0..3；协议 byte2 只有 2 bit | 与"无级强度"的设计结论不一致，患者临界点找不到 | 随 v11 的 byte2 高 4 bit 升为百分比（协议已预留） |
| C5 | **会话时钟是本地推算** | `sessionElapsedMs` 用 `SystemClock` 起算；v11 已有 `elapsedSec` 未使用 | 断链重连后与头显不一致，志愿者记录的时间不可信 | 优先用 `control.elapsedSec`，为 0 时回退本地 |
| C6 | **错误不会自清** | `error` 仅在下一次发送成功或重连时清 | 一条"头显未确认命令"可以停留整场会话，掩盖新问题 | 错误 15 s 自动收起，或新状态到达即清 |
| C7 | **退出系统一键三连** | `exitSystem()` 连发 `stop`、`exit`、`home` | 无确认；断链时三条各报一次错 | 加确认；发送前检查 `READY`，避免三连错误 |
| C8 | **多台头显无法选择** | 扫描匹配第一台即连（`docs/control-plane.md` §2） | 病房多床会接错设备——错误的时间在错误的耳边出声 | 配对列表（名称 + 尾号 + RSSI），记上次设备并高亮 |
| C9 | **能力位全匹配** | `CAPABILITIES_MASK` 要求逐位一致 | 任一端加能力，另一端整体握手失败 | 改成"必需位子集"：缺可选能力只禁用对应控件 |
| C10 | **没有操作日志** | 只有瞬时 `notice` | 培训复盘、志愿者记录、事故回溯都缺证据 | 本地环形日志（时间、命令、ACK），只在状态面板可见 |
| C11 | **文档与代码继续背离** | `core.md` 写单场景；平板有 `ScenePage`；现在要做到第三个场景 | 新人无从判断哪个是对的 | 场景数量写进 `core.md` 决策表，并同步协议与两端 |
| C12 | **顶栏过密** | 紧凑模式（<1000 dp）下 6 个文字按钮 | 戴手套点错的概率上升 | 顶栏只留"状态/语音/断开"，其余进一个"更多" |

## 3 可培训性

操作员必须能独立完成 7 件事，现状只覆盖了 5 件：

| # | 任务 | 现状 |
| --- | --- | --- |
| 1 | 打开头显、确认蓝牙与平板配对 | 配对页有 3 步说明 |
| 2 | 选择场景（现在有三个） | 有，但卡片只写名字，不写"适合谁" |
| 3 | 设定模式/强度/档位 | 有，但"档位 a/b/c"没有解释它同时改幅度与周期 |
| 4 | 启动并等患者按确认键 | **缺**：没有等待态（C1） |
| 5 | 会话中调整 + 说引导语 | 有；语音面板尚无"下一句是哪句"（自动模式只在页面里跑） |
| 6 | 停止（患者/技术员/断链） | 有，但三种停止在界面上无法区分（C3） |
| 7 | 收尾与记录 | **缺**：无操作日志（C10），时钟不可信（C5） |

具体缺口：

- **术语**：朝向 / 校准 / 档位 / 能力位 都直接出现在界面，没有解释入口；头显控制台有"帮助"页，平板没有。
- **错误文案**：`头显未确认命令：float:level:2` 是给开发者看的。应为"头显没有回应，请靠近或重启头显应用"，并把命令名留在日志里。
- **单一指示**：屏幕没有回答"现在该做什么"的那一行；状态分散在标题、按钮、提示条三处。
- **演练**：没有"无患者干跑"模式；培训只能拿真患者练。

## 4 培训脚本（30 分钟）

| 时段 | 内容 | 交付物 |
| --- | --- | --- |
| 0–5 min | 角色分工：患者只按确认键；技术员负责一切设置与停止 | 一句话能复述 |
| 5–15 min | 无患者干跑：配对 → 选场景 → 设置 → 启动 → 等确认 → 调到强度 2 → 结束 | 独立完成 1 次 |
| 15–25 min | 三个故障：拔掉头显电源（断链）、患者自己按停、接错头显（两个设备在场） | 每次 ≤15 s 恢复 |
| 25–30 min | 考核：不看提示完成 3 个场景各一次；说出两条停止路径 | 5 项全过 |

考核点（可打分）：启动前是否确认患者躺好；是否在患者确认前就离开床边；断链后是否先看屏幕再看设备；是否知道急停不需要平板。

## 5 改进顺序

| 优先级 | 项 | 验收 |
| --- | --- | --- |
| P0 | C1 等待患者确认态 | 启动后按钮不可点，标题显示"等待患者确认"，20 s 后自动回到待机并提示 |
| P0 | C2 校准相可见 | 校准期间标题与提示条同时变化，会话时钟停止计时 |
| P0 | C5 时钟改用 `elapsedSec` | 断开 5 s 再连回，时钟与头显一致（差 ≤1 s） |
| P1 | C3 停止语义 | 只有一个"结束"；急停独立常驻，按下后 1 s 内可见"已停止" |
| P1 | C6 错误自清 | 15 s 后自动收起，新错误覆盖旧错误 |
| P1 | C8 设备列表 | 两台头显同场时能选对，显示尾号与 RSSI |
| P2 | C10 操作日志 | 状态面板可展开最近 20 条（时间/命令/结果） |
| P2 | C11 场景数量入文档 | `core.md` 决策表写明当前三个场景与默认值 |
| P2 | C12 顶栏收敛 | 紧凑模式顶栏 ≤3 个按钮 |

## 6 已可直接做的三项（本轮实现）

1. **等待患者确认**：新增 `startPending`，20 s 超时或 `session` 上升沿清除；启动按钮在期间置灰并改文案。
2. **校准相**：会话标题与提示行读取 `control.calibrating`；校准期间时钟不计时。
3. **时钟**：优先 `control.elapsedSec`（v11），为 0 时回退本地秒表。

其余项需要一次协议/界面小改，按上表顺序做。
