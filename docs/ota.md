# OTA 与远程收集：调研存档（结论：不做）

状态：2026-11-13 调研完毕。**结论是不做**，这份文档只作为调查记录留存：把当时的约束、
两个候选方案、服务器现况和否决理由写下来，免得下一次再从头论证一遍。

**不做的理由**：
1. 更新是低频事件（当前发布节奏以周计），而实现成本是整个客户端加一个服务端；
   侧载一次 APK 的成本远低于维护一条更新通道。
2. Android 8.1 没有静默安装，更新必然有一次系统确认。省不掉的那次确认，
   意味着“零点击”从来不是这套方案能给的收益。
3. 只升一端会让协议整帧拒收，成对升级必须靠额外的一致性机制兜住——
   为一个低频动作引入一个必须永远正确的机制，不划算。
4. 记录收集与“离线、不上传”的产品承诺直接冲突；默认关闭时它没有价值，
   打开时它需要伦理与知情同意的额外工作。

**离线仍是硬约束**：没有网络、没有服务器、没有任何账号时，VR 头显 + 平板 的进入、
控制、记录、导出全部可用。记录只在本机，导出走系统分享。

## 1. 现况

| 项 | 事实 | 依据 |
| --- | --- | --- |
| 分发 | 手工侧载两个 APK；发布物仍是 debug 变体 + 可选 re-sign | `.github/workflows/release.yml:129-194` |
| 版本 | `package.json` 2.0.0；headset `versionCode 201`、control `200` | `android/*/build.gradle.kts` |
| 版本一致性 | 头显与平板必须同版本（协议 v14 整帧拒收，`HELLO 2`/`WELCOME 2` 握手） | `ControlProtocol.kt:39-41` |
| 站点 | 已有静态站 `site/`，未托管在服务器上 | `site/deploy.sh` |
| 服务器 | Debian 12；Caddy 占 80/443（自动 TLS）；Docker 在跑；`/var/www` 存在；根分区 36 G 可用 | 只读 `ssh yecaoyun` |
| 记录 | 会话摘要 + 问卷答卷 + 行为事件都在平板本机，导出走系统分享 | `data/EventLog.kt`、`data/TrainingStore.kt`、`data/SusStore.kt` |

关键约束：**Android 8.1 上没有静默安装**。除非设备被做成 device-owner（PICO G2 不是），
装 APK 必然有一次系统确认对话框。任何“零点击更新”的方案都以此为前提，不成立。

## 2. 两个方案

### A. 应用内检查 + 下载 + `PackageInstaller`

```
[平板/头显] --HTTPS GET--> https://host/qs/manifest.json
                              ↓ 高于本机 versionCode 且签名/哈希匹配
                          [后台下载到 cache] --校验--> 应用内弹“安装” --> 系统确认对话框
```

- 权限：`INTERNET`（两端已有）、`REQUEST_INSTALL_PACKAGES`。
- 触发：**只由技术员按键触发**（说明书页的「检查更新」）。开机会话路径上不检查，
  连不上服务器不算错误、不弹横幅、不阻塞任何操作。
- 校验：`sha256` + `apksigner` 证书指纹必须与已安装包一致（`PackageManager.getPackageInfo`
  的 `signatures`），否则拒绝安装并记录事件。
- 成对升级：manifest 里两个 APK 共享一个 `pair` 哈希；只匹配到一半时**不提示**，
  因为头显与平板版本不一致比旧版本更糟（协议整帧拒收）。
- 回滚：下载与安装之间保留上一版 APK 于 `filesDir/lkg/`；新版本启动若连续两次在
  前 60 s 内崩溃，标记该版本坏并提示侧载回退。**不做静默降级**——8.1 会拒绝降级安装。

代价：每次更新在头显里还有一次系统确认，需要人伸手。这正是本品类里可接受的成本。

### B. 服务器侧 adb 推送

- 需要设备常开 ADB 调试、与服务器同网、且 adb key 已授信；`adb install -r` 可脚本化。
- 优点：真正零点击，两 APK 可原子成对升级。
- 缺点：把“联网调试口”常开在临床设备上，安全面远大于收益；网络变动即失效。
- 结论：仅在实验室/受控维护窗口使用，**不作为产品通道**。

### 比较

| 维度 | A 应用内 | B adb 推送 |
| --- | --- | --- |
| 离线可用 | 不受影响 | 不受影响 |
| 更新点击次数 | 技术员 1 次 + 系统确认 1 次 | 0 |
| 设备安全面 | 只有 HTTPS 出站 | 常开 ADB |
| 失败可见性 | 应用内状态可记录 | 依赖服务器日志 |
| 结论 | 未采用 | 未采用 |

## 3. manifest 契约

固定 URL：`https://<host>/qs/manifest.json`（Caddy 托管 `/qs/` 静态目录）。

```json
{
  "format": 1,
  "pair": "sha256:9f2c…",
  "channel": "ward",
  "notes": "2.1.0：移除流程编排，新增适应阶段",
  "artifacts": {
    "control": {
      "versionCode": 210,
      "versionName": "2.1.0",
      "file": "quiet-shore-control-2.1.0.apk",
      "size": 18061400,
      "sha256": "…"
    },
    "headset": {
      "versionCode": 211,
      "versionName": "2.1.0",
      "file": "quiet-shore-headset-2.1.0.apk",
      "size": 4008901,
      "sha256": "…"
    }
  }
}
```

规则：

1. `format` 不认识就地停止，不猜。
2. `pair` = 两个 APK 的 `sha256` 排序后拼接再哈希；两端计算同一值，只报“有一对可升”。
3. 缺任一端 → 视为不可升级（一致性优先于新鲜度）。
4. manifest 与 APK 都走 HTTPS；Caddy 的证书是唯一信任根，不引入自签。

## 4. 状态机（更新，全部本地、可断电）

```
idle ──技术员按「检查更新」──> checking ──无更新──> idle(已是最新)
                                 │
                                 ├─有更新─> available ──下载──> downloading
                                 │                              │
                                 │                    ┌─────────┴────────┐
                                 │                 校验失败            校验通过
                                 │                    │                  │
                                 │                 idle(失败, 记录)   ready
                                 │                                     │
                                 └────────────────────────────> installing → 系统确认
                                                                       │
                                                              成功 → 事件记录 → idle
                                                              取消 → idle（不重试）
```

- 下载支持断点续传（`Range`），失败重试 3 次后停；**不自动重试到下一次开机**。
- 下载只在 `WIFI`/以太网且电量 ≥ 30% 时进行；会话进行中一律不下载。
- 所有转移写 `EventLog`（`update.*`），导出时可见。

## 5. 远程数据收集（默认关闭）

原则：**记录只在本机，直到有人明确要它**。

1. **默认关闭**。安装时无开关，`Settings` 里只有一处「允许上传记录」，默认关。
2. **显式授权**：打开开关时弹一次说明（上传什么、传到哪、怎么删），取消即恢复关闭。
3. **手工或挂起时上传**：`导出本机记录` 旁另设「上传记录」，一次一份 JSON；
   不做后台常驻上传。
4. **脱敏**：不采集姓名、住院号、床号、人脸、画面、音频；设备标识只用安装时生成的
   随机 `deviceId`（可重置）。事件里只有 app/kind/时间/数值。
5. **失败不丢**：上传队列在本地（`filesDir/uploads/`），成功才删；离线时静默排队。
6. **删除**：设置里「清除本机记录」同时清空队列；服务器端保留 90 天后自动删除。
7. **服务端**：Caddy `handle /qs/ingest` 反代到一个只做「落盘 + 追加写入」的小服务
   （按 `deviceId` 分目录，写 JSONL）。不需要数据库。

## 6. 服务器落地（最小面）

```
/srv/qs/
  manifest.json                 # 手写/发布时生成
  *.apk                         # 两个产物
  SHA256SUMS.txt
```

Caddyfile（现有站点追加，不新建端口）：

```
handle /qs/* {
    root * /srv/qs
    file_server
    header Cache-Control "no-cache"
}
```

发布动作：`sha256sum` → 生成 manifest → `rsync` 到 `/srv/qs/` → 设备侧键「检查更新」。

## 7. 不做的事

- 不做静默安装 / device-owner / 系统签名。
- 不做后台定时上传，不做账号体系。
- 不在会话路径上做任何网络探测。
- 不用自签证书或 IP 直连。
- 不用 adb 常开作为产品通道。

## 8. 若要重开，按这个顺序（当前不执行）

1. 服务器：`/srv/qs/` + Caddy `handle` 段 + 一个发布脚本（生成 manifest 与 pair）。
2. 平板：manifest 拉取 + 校验 + 下载 + `PackageInstaller` + 状态机 + 事件记录。
3. 头显：同一份实现复用（`versionCode` 独立，`pair` 共享）。
4. 设置里的「允许上传记录」+ 上传队列 + 服务端落盘。
5. 真机验证：断网不报错、半对更新不提示、签名不匹配拒绝、取消安装不留残状态。

## 9. 若重开的风险

| 风险 | 处置 |
| --- | --- |
| 8.1 拒绝降级安装 | 只提供向上更新；坏版本靠侧载回退，并在 manifest 里明确标记 |
| 只升一端导致协议整帧拒收 | `pair` 哈希强制成对 |
| 临床设备联网面扩大 | 只出站 HTTPS；无监听口；无账号 |
| 上传被误解为“监控” | 默认关、逐次授权、脱敏清单写进说明与知情同意 |
| Caddy 证书过期 | 现有站点已在用同一证书；监控告警沿用服务器现有手段 |
