# 业务母目标（v1 定的，v2 不改）

2026-11-12 由用户明确：这套系统的母目标是——

> **通过施加俯仰角度的偏移，引导患者想象站立，降低床上排尿的心理障碍。**

## 1 机制链

```
技术员记录起始体位（校准）
  → 画面把视野从"仰卧看到的天花板"抬到"站立看到的水平"
  → 患者在场景里逐步适应这个视角（场景是载体，不是目的）
  → 俯仰角可调、可维持、可撤回
  → 心理障碍降低：能想象自己站着 → 能在床上排尿
```

- **核心是俯仰偏移**（`mix` + `viewPitch` + 眼高），不是"看了几个场景"。
- 场景提供的是**情境**（病房、立便间、湖面）：让"站立"这件事在某处发生，而不是让人盯着一个抽象的角度数字。
- 漂浮/起伏是**辅助**：把静止的偏移变成缓慢的运动，减轻"身体没动但视野变了"的别扭感。
- 语音引导是**认知脚手架**：把"想象自己站着"说出来、说到位。

## 2 对 v2 的约束

| 约束 | 含义 |
| --- | --- |
| 任何新场景必须服务这条链 | 新主题可以先问：它让"仰卧的人想象站立"更容易，还是只是好看？ |
| 校准的地位不可降级 | 它是偏移的基准点；没有基准，"抬到站立"就没有参照 |
| 偏移要可读、可停、可回 | 技术员必须随时知道当前角度离站立还有多远，也能退回躺平 |
| 流程要覆盖"适应"而不是"播放" | 一次会话的目标是让人在偏移视角里待住，所以时长、渐进、分段比"场景多"更重要 |

**协议、说明书、界面文案都可以换代**（用户已明确：v1 的流程/协议/文档不需要兼容），但上面这条机制链与母目标不变。

## 3 现在系统里对应的实现

| 机制 | 代码 |
| --- | --- |
| 基准：记录起始体位 | `App.beginCalibration`（v2 改为技术员显式触发） |
| 偏移：`mix` 0→1 把世界从仰卧抬到站立 | `core/world-frame.ts`、`core/xr/world` |
| 眼高：躺姿由解剖推导，站姿由技术员设定 | `core/anatomy.ts`、`ControlState.eyeHeight` |
| 维持：会话中不动、不被场景切换打断 | `switchSceneLive`（保留校准帧与视线偏移） |
| 撤回：结束淡出、`view:anim:down`、`posture:lower` | `App.requestStop`、view-motion |

## 4 尚缺的一环

**没有任何地方记录"这次偏移到了多少、患者待了多久、他/她感觉如何"**——
会话台账（`session-log.ts`、平板会话台账）记了时长与场景，但没记**到达的偏移角度**与**主观感受**。

业务上的下一步应该是：

1. 台账增加 `peakMix`（本次会话到达的最大 `mix`）、`peakPitchDeg`、每段停留时长。
2. SUS 之外补一个**床上排尿相关的自评**（一次二选一即可：这次有没有试、成没成），并与台账关联。
3. 这三个数才是"系统有没有用"的证据，而不是"用了多少分钟"。
