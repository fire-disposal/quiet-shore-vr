# v2 路线：界面之后

状态：2026-11-12。v1.0.0 已冻结（`docs/releases.md`），界面重做在进行中；本页记 v2 的
其余方向与它们的依赖，不写实现细节——实现落进各自的事实来源文档。

## 0 v1.0.0 的边界

v1.0.0 = 四场景 × 一套运动学（体位 / 起伏 / 视线）× 状态帧 v13 × 语音序列 × 会话台账。
界面是深色命令栏 + 页签 + 快捷行。**场景内容与交互自 0.9 起没有本质变化**：每个场景是一段
可以一直看下去的画面，会话时长由技术员决定，场景内部没有时间结构。v2 从这个结论出发。

## 1 场景流程加长（v2 主线）

现在的场景是**一个稳态**：进入即开始，离开即结束。患者在里面待 10 分钟看到的还是同一段
画面、同一层声音。v2 要把它改成**一段有起承转合的流程**。

### 1.1 场景获得时间线

`SceneDefinition` 增加可选 `phases`：每段声明

| 字段 | 含义 |
| --- | --- |
| `id` | `enter` / `unfold` / `dwell` / `close`（名字待定，但必须与语音序列对得上） |
| `durationSec` | 该段名义时长，应用可按会话时长伸缩 |
| `motion` | 该段允许的自走幅度（沿用 `setMotion(0..1)`，不新增通道） |
| `cue` | 该段对应的语音序列（`start` / `imagine` / `relax` / `close`） |
| `look` | 构图/光照/雾的渐变目标（每段一个值，应用负责插值） |

应用仍是唯一推时间的角色：场景不自己起定时器（`docs/scenes.md` 的边界不变），只声明阶段表。

### 1.2 时长

- 单场景名义流程从“无”变到 **8–12 分钟**，按 3–4 段分配；技术员仍可提前结束。
- 会话时长与流程时长解耦：选 6 分钟会话就按比例压缩段落，而不是砍掉最后一段。
- 计时仍由头显计（平板不推算），台账记录实际段落进度以供复盘。

### 1.3 为什么现在不能直接加

1. 场景契约里没有时间概念，`update(dt, elapsed)` 只拿到累计时间；加阶段要动契约与四个场景。
2. 语音序列与段落没有绑定：现在语音是独立播放器，段落推进时语音可能正在念上一段。
3. 结束淡出与段落收束会打架：两者都改世界外观，要有明确优先级（结束 > 段落渐变）。

### 1.4 验收

- 同一场景 10 分钟会话内，画面/声音能看出至少三次变化，且没有跳变。
- 段落推进与语音序列对齐；提前结束不出现“语音还在念、画面已经黑了”。
- 断链重连后，段落进度与计时一致，不重头开始。

## 2 场景质量

在**不加预算**的前提下提升，顺序按性价比：

| 项 | 目标 | 现在的状况 |
| --- | --- | --- |
| 构图纵深 | 每场景至少三层可辨的前中后景 | 已有，但远景多为贴片 |
| 光照层次 | 主光 + 补光 + 环境遮蔽感；不出现纯黑死区 | 单方向光为主 |
| 材质 | 水面/雾/墙面各自有独立响应 | 已有基础，缺细节法线 |
| 音景 | 底噪 + 中景 + 事件声三层 | 只有水声床 |
| 动画密度 | 近景有缓慢周期运动，远景静止 | 有，但周期偏短、易被察觉 |
| 预算 | 维持既有 draw call / 三角面 / 纹理预算（`tests/scenes.test.ts` 断言） | 见 `docs/tuning-defaults.md` |

## 3 会话中切换场景

见 `docs/scene-switch.md`。已能跑，过渡与朝向连续性未设计，v2 界面暂不放出入口。

## 4 依赖顺序

1. 界面重做落地（进行中）→ 升 v2.0.0。
2. 场景契约加 `phases` + 应用推时间线（改动面最大，先做四个场景中的 `shore` 作样板）。
3. 语音序列与段落绑定；结束淡出优先级。
4. 场景质量逐项提升，每项都在 `tests/scenes.test.ts` 的预算断言下做。
5. 会话中切换的过渡设计（依赖 2）。
