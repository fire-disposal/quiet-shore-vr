# UI 审计：草稿 `~/dev/VR` 的经验与局限

> 历史文档。文中的两步校准（天花板/脚尖）、1.2 s 注视停留与四模式面板 lab 均已被现状取代：校准改为一步（正前方 + 静止），注视停留统一 6 s，`lab` 改为站立参照场景。当前事实见 `control-interaction-spec.md`、`virtual-posture.md`、`spatial-ui.md`。

审计对象是草稿实现，不是新库目标。证据来自 `src/styles.css`、`src/index.html`、`src/ui/*.ts`、`src/vr/gaze.ts`、`src/vr/calibration.ts` 与 `README.md` 的实机结论。

## 1. 现有视觉语言

| 维度 | 现状 | 判断 |
| --- | --- | --- |
| 色调 | GitHub Dark：`#0d1117` 底、`#151b24` 面、`#2d3947` 边、`#1f6feb` 主色 | 工程工具感强，不像患者产品 |
| 字体 | DOM 用 system-ui；XR 面板与 HUD 用 monospace | 两套字体体系；中文 monospace 实际回退到系统 sans，字距不稳 |
| 圆角/边框 | 2D 按钮 12px、场景卡 14px；XR 面板直角描边 | 2D 与 3D 不一致 |
| 信息密度 | 首屏包含品牌、状态、场景卡、统计、两组按钮、三行提示 | 对患者过高；对操作员仍不够 |
| 动效 | 选中缩放 1.12、注视 dwell 环、无面板进出场 | 有反馈，但缺少可预测的召唤/消失过渡 |
| 文本实现 | CanvasTexture 绘制固定文案 | 老设备可控，但无法动态排版、无本地化层、清晰度依赖分辨率 |

## 2. 各界面现状

### 2.1 2D 启动页

做得好的：

- 单列、最大宽度 720px，短屏可滚动；按钮最小高度 62px，场景卡 128px，触控目标充足。
- 场景卡有 `aria-pressed`、`aria-live` 提示、`focus-visible`、方向键/Home/End 导航。
- 文案是中文，面向患者；场景说明简短。
- `?quality=low`、`?aa=0`、`?scene=`、`?nocal=1` 提供了低成本调试入口。

局限：

- 首屏把 FPS、draw call、三角形数、校准状态、注视次数直接暴露给患者；这些是操作员信息。
- 标题绑定硬件 `舒缓灵景 · PICO G2 4K`，换设备或换渠道就失效。
- 三行长提示（校准、菜单、浏览器限制）挤占首屏；患者只需要一个主行动。
- “进入 VR”禁用时只靠状态行解释，没有就近的错误/引导。
- 场景选择与进入按钮的层级接近；患者可能先纠结场景而不是进入。
- 没有语言切换、字号设置、降低动效、dwell 时长等可访问性选项。

### 2.2 XR 菜单

做得好的：

- 召唤位置基于头部朝向，`y` 方向夹在 -12°..+28°，避免出现在头顶/脚下。
- 召唤后世界锁定，符合“看一眼、操作、放下”的短任务模型。
- 注视 hover + 短按确认，适合 3DoF 头显；面板 `depthTest: false`、`renderOrder` 高，保证可读。
- 面板尺寸 0.84×0.70 m、距离 1.15 m，视觉角度较大，老设备也看得清。

局限：

- 召唤、世界锁定、朝向计算、hover、reticle、销毁全部写在一个 355 行文件里，无法复用。
- 面板是直角描边、monospace、无背景模糊/阴影/圆角；与 2D UI 不是一套设计语言。
- 面板出现/消失是硬切，没有缩放/淡入/焦点转移。
- 菜单打开时只是隐藏场景 gaze reticle，输入系统仍是两套 raycaster。
- 没有“菜单已打开”的空间音/触觉反馈；3DoF 下用户可能不知道菜单在哪。
- 按钮命中区与视觉尺寸一致，但没有最小视角保证；远距离/边缘注视成本高。
- 文本是 512×96 的 CanvasTexture，固定字号；中文长标签会溢出，英文/多语言无法适配。

### 2.3 校准卡

做得好的：

- 两步校准（天花板、脚尖）符合卧床患者的实际姿态；6° 抖动门限 + 600ms 稳定 + 2s 倒计时，容错合理。
- 视图锁定 rig 每帧复制头 pose，卡片始终在视野中心；中心环提供 3D 进度反馈。
- 失败原因（toes-zero、poses-parallel、poses-too-similar）可诊断。

局限：

- 视图锁定是硬编码的另一个空间模式，和菜单各写一套 pose 复制逻辑。
- 卡片距离 0.75 m、尺寸 0.64×0.32 m，近距离辐辏压力偏大；长时间校准可能不适。
- 倒计时/进度用 Canvas 重绘，文本与环形反馈分离；没有统一的“空间提示”组件。
- 校准期间隐藏世界，只留黑底；对已经晕动的用户可能更迷失，缺少渐进过渡。
- 校准状态只存在于 HUD/状态行，没有可复用的状态机契约。

### 2.4 注视、准星与场景选择

做得好的：

- 严格中心角门限（默认 0.6°）+ 1.2s dwell + latch，避免误触和重复触发。
- 准星是 3D ring，不是 DOM；在 XR 中可见。
- 场景 `selectables` 由场景模块提供，交互与场景解耦了一半。

局限：

- 场景 gaze 与菜单 gaze 是两个 raycaster；hover/选中/准星样式不一致。
- `gaze-spin` 是测试辅助，却在主循环里默认启用；患者可能看到物体无故旋转。
- 没有控制器射线/手柄模型；3DoF 手柄只用于 `select` 事件。
- 没有“注视目标太远/太小”的提示；`maxDistance=12` 对远处物体仍可选中。
- 没有 dwell 进度在目标上的空间反馈（只有准星颜色），患者不知道还要看多久。

### 2.5 HUD 与操作员信息

- HUD 是 DOM 覆盖层，只在 2D 预览可见；XR 内没有等价调试面板。
- 信息包含 FPS、模式、场景、校准、画质、AA、注视次数、声音、菜单提示；对开发有用，对患者是噪声。
- 没有日志/错误面板；`window.__app` 是隐式调试 API，不是契约。

## 3. 体验层面的结论

### 有效经验

1. **3DoF 头显上，头部注视 + 确认键是可靠输入**；不要假设有 6DoF 手柄射线。
2. **短任务 UI 用“召唤后世界锁定”最稳**；长期跟随视角会晕。
3. **校准必须容错**：角度门限、稳定窗口、失败原因、可重试，比“精确对准”重要。
4. **低画质档/AA/帧缓冲缩放是 Adreno 540 的必要杠杆**；UI 也要遵守同样的预算。
5. **2D 启动页的键盘/ARIA 基础是资产**，不要因为换 XR 框架丢掉。
6. **场景与交互解耦**（`selectables`）方向正确，应该升级为正式契约。

### 主要局限

1. **患者 UI 与操作员 UI 混在一起**；首屏和 HUD 暴露工程指标。
2. **空间 UI 没有抽象**；四种模式中只实现了“召唤后世界锁定”和“头锁定”，且各写一套。
3. **文本/主题/字符串没有单一事实源**；Canvas 纹理、DOM CSS、Java 字符串三套。
4. **输入系统重复**；场景 gaze、菜单 gaze、准星各自 raycast。
5. **缺少空间 UI 的生命周期**：创建、显示、聚焦、选中、关闭、销毁没有统一契约。
6. **缺少舒适性策略**：头锁定阻尼、淡入淡出、recenter、减少动效、dwell 可调都没有。
7. **缺少可访问性与 i18n**；中文硬编码，英文只存在于 README。
8. **性能预算只覆盖场景，不覆盖 UI**；每个面板都是独立 CanvasTexture/Material，场景切换时容易泄漏。

## 4. 新库的设计方向

### 4.1 双界面层

- **患者层（默认）**：一个主行动、场景可选、无 FPS/draw call、短提示、低刺激。
- **操作员层（显式开启）**：校准、诊断、空间 UI 实验、性能统计；通过 `?debug=1` 或隐藏入口进入。

### 4.2 一套空间 UI 设计语言

- 深青灰底 + 暖沙色强调，避免 GitHub 蓝的工程感；保留高对比。
- 圆角面板、细边框、轻背景遮罩；统一 8px 网格。
- 中文优先的 CJK sans；数字/单位可用等宽作为次级风格，不把 monospace 当主字体。
- 面板距离 1.2–1.6 m；标题字号对应视角 ≥ 1.2°，正文 ≥ 0.8°；按钮命中区 ≥ 2°。
- 进场：120–180ms 缩放 0.96→1 + 透明度；退场反向；尊重减少动效。
- 统一 `SpatialSurface`/`SpatialButton`/`SpatialInput`，禁止各界面自建 raycaster/面板。

### 4.3 四种空间模式作为一等契约

1. `summoned`：召唤时在视角前方生成，随后冻结在世界；菜单/对话框默认。
2. `head-locked`：跟随头部；仅用于校准、瞬时提示；带阻尼，禁止长期常驻。
3. `world-locked`：固定世界位姿；场景标签、锚点。
4. `world-billboard`：固定位置，朝向用户；默认仅 yaw，避免俯仰导致阅读变形。

### 4.4 文本策略

- 固定文案：CanvasTexture 缓存（key = 文本+字体+字号+颜色+宽度），2x 分辨率、mipmap、anisotropy。
- 动态数值：几何/进度环，不每帧重绘文本。
- 中文 fallback：`"Noto Sans CJK SC", "Source Han Sans SC", "PingFang SC", sans-serif`；在真机验证字重与可读性。
- 所有文案进 `ui/strings.ts`，中文默认、英文可选；Java 侧字符串单独集中。

### 4.5 验收标准

- 首屏无 FPS/draw call/三角形数；调试信息只在 `?debug=1`。
- 菜单、校准、场景标签、billboard 标签分别使用四种 `SpatialMode`，不复制 pose 代码。
- 场景 gaze 与 UI gaze 共用一个 `SpatialInput`；同一帧只有一个 raycaster 服务。
- 所有空间面板的 geometry/material/texture 在关闭/卸载时可释放；重复开关 50 次不增长。
- 头锁定面板有阻尼且可配置；减少动效模式下进场无缩放。
- 2D 首屏保留键盘/ARIA；新增语言、字号、dwell 时长的设置入口（可先隐藏）。
